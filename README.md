# Bright Dash

Build a modern, responsive web application based on the screenshot I have attached.

IMPORTANT: The attached screenshot is ONLY a visual design reference. Use it to understand the layout, spacing, typography, colors, cards, navigation, buttons, dashboard structure, and overall visual style.

Do NOT copy or implement any business rules, financial calculations, transaction requirements, withdrawal fees, service charges, taxes, verification fees, payment prompts, or other financial logic that may appear in the screenshot.

In particular:

Do NOT add withdrawal fees.

Do NOT add processing fees or service charges.

Do NOT add taxes or hidden charges.

Do NOT create any requirement for users to pay money before withdrawing.

Do NOT add fake transaction restrictions or financial conditions based on the screenshot.

Do NOT assume that text or numbers shown in the screenshot represent actual functionality.

Treat all numbers, balances, fees, transactions, names, and financial information in the screenshot as placeholder visual content only.

What I want you to build

Create the web app with the same general visual direction and dashboard experience as the screenshot, while making the application itself clean, functional, and easy to customize.

The app should include:

Dashboard/Homepage



The dashboard should be the main homepage after login.

Modern sidebar/navigation.

Header/top navigation.

Summary cards.

Relevant charts or activity sections where appropriate.

Responsive layout for desktop, tablet, and mobile.

Clean UI



Closely reproduce the screenshot’s visual hierarchy.

Match the general spacing, proportions, card styling, typography, border radius, icons, and navigation style.

Keep the design polished and professional.

Do not blindly copy elements that don’t make sense for the new application.

Functional interactions



Navigation should work.

Buttons should have appropriate interactions.

Menus should open/close correctly.

Responsive mobile navigation should work.

Use realistic placeholder/demo data where necessary.

No unnecessary financial logic



If the screenshot contains financial information, treat it purely as sample UI.

Do not create withdrawal-fee functionality or any other fee-based workflow.

A withdrawal action, if included as part of the UI, should simply demonstrate the interface without requiring a user to pay an additional fee.

Code quality



Use a clean, maintainable component structure.

Make the application responsive.

Avoid unnecessary dependencies.

Keep the code organized and easy to modify later.

Before implementing anything, analyze the attached screenshot for its visual design only and use that analysis to create the interface.

The screenshot is not a specification of the app’s business logic. It is strictly a reference for how I want the website/app to look.
